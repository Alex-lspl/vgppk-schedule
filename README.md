# Расписание ВГППК

Альтернативный вид страницы https://rasp.vgppk.ru/bg203.htm: то же расписание, но удобное на телефоне и компьютере, с отметками об изменениях и панелью администратора для срочных замен.

## Принцип работы

```text
┌────────────────────────┐              ┌────────────────────────┐
│ Сайт колледжа          │              │ Админка (/admin)       │
│ rasp.vgppk.ru          │              │ правки, поиск, Gemini  │
└────────────────────────┘              └────────────────────────┘
            │ HTML                                  │ правки
            ▼                                       ▼
┌────────────────────────────────────────────────────────────────┐
│ Серверные функции Vercel (/api/*)                              │
│ разбор HTML · исправления · отметки изменений                  │
│ ручные правки · каталог · кэш на CDN                           │
└────────────────────────────────────────────────────────────────┘

            │ JSON                          ▲ чтение    │ запись
            ▼                               │           ▼
┌────────────────────────┐      ┌────────────────────────────────┐
│ Сайт для студентов     │      │ GitHub, ветка с данными        │
│ (public/)              │      │ overrides · changes · catalog  │
└────────────────────────┘      └────────────────────────────────┘
```

| Компонент | Назначение | Где находится |
| --- | --- | --- |
| Сайт для студентов | Показ двух недель расписания, звонков, отметок об изменениях | `views/index.html` (отдаётся через `api/gate.js`), `public/app.js`, `public/style.css` |
| Проверка доступа | Заглушка «сайт не работает», вход по паролю, служебные страницы | `api/gate.js`, `lib/access.js`, `lib/settings.js`, `lib/pages.js`, `public/pages.css`, `public/gate.js`, `public/404.html` |
| Загрузка и разбор | Получение HTML колледжа, преобразование в JSON, встроенные исправления | `lib/fetchPage.js`, `lib/parse.js`, `lib/fixes.js` |
| Отметки изменений | Сравнение со снимком расписания, отметка действует 24 часа | `lib/changes.js`, `data/changes.json` |
| Ручные правки | Хранение и наложение правок по календарным неделям | `lib/overrides.js`, `data/overrides.json` |
| Каталог | Группы, предметы, преподаватели, аудитории для подсказок | `lib/catalog.js`, `data/catalog.json` |
| Админка | Редактор двух недель, поиск, автозаполнение через Gemini | `public/admin-assets/`, `api/admin*.js` |
| Статистика и настройки | Сбор сигналов с сайта, онлайн и посетители (`/admin/stats`), настройки сайта (`/admin/settings`) | `lib/stats.js`, `lib/statsPage.js`, `lib/settingsPage.js`, `api/visit.js`, `api/admin-stats.js`, `public/admin-assets/stats.*`, `public/admin-assets/settings.*` |
| Авторизация | Вход администратора, подписанные сессии, защита от перебора | `lib/adminAuth.js`, `lib/rateLimit.js` |
| Хранилище | Чтение и запись JSON-файлов через GitHub Contents API | `lib/githubStore.js` |
| Хранилище статистики | Upstash Redis (необязательно), записи посетителей на 30 дней | `lib/stats.js` |

Сайт колледжа не отдаёт данные в удобном виде, поэтому серверная функция забирает HTML, разбирает его в JSON и кэширует ответ. Ручные правки, служебные снимки и каталог хранятся JSON-файлами в самом репозитории, отдельная база данных не нужна.

## Возможности сайта

- Две недели расписания («Неделя 1» и «Неделя 2») с датами, дни недели с подсветкой текущего дня.
- Подгруппы: переключатель «Все / 1 подгр. / 2 подгр.», выбор запоминается.
- Звонки, подсветка идущей пары и обеденного перерыва.
- Работа без сети по последним сохранённым данным.
- **Отметка об изменении.** Если пара изменилась за последние 24 часа, слева от номера аудитории показывается значок, такой же, как у строки состояния. По нажатию открывается подсказка: изменение внесено автоматически (обновление на сайте колледжа) или вручную, и когда это произошло.
- **Выключение сайта и вход по паролю.** Из админки сайт можно временно выключить (заглушка с вашим текстом) или закрыть логином и паролем для посетителей; есть страница 404 (см. «Настройки сайта»).
- **Анонимная статистика.** Сайт отправляет короткие сигналы «я тут», по ним в админке считаются онлайн и посетители (см. раздел «Статистика посещений»).
- **Главная и запоминание группы.** При первом заходе открывается главная: поиск и плитки всех групп (список берётся из `/api/groups` и сохраняется на устройстве, поэтому открывается мгновенно и без сети). Выбранная группа запоминается в `localStorage` браузера (куки не используются, на сервер выбор не отправляется), и при следующем заходе сразу открывается её расписание. Кнопка с номером группы в шапке возвращает на главную; системная кнопка «Назад» на телефоне ведёт обратно к расписанию. Ссылка вида `/?page=bg203` по-прежнему открывает нужную группу сразу.
- **Telegram в подвале.** Ссылка ведёт на `https://t.me/…`: она открывает приложение, если оно есть, а без него — веб-версию в браузере (старая `tg://` без установленного приложения не делала ничего). Рядом кнопка копирования `@l_SP_Soft_l` — на случай, если Telegram недоступен.
- **Версия.** В нижней части страницы, справа от ссылки на Telegram, показывается версия приложения. Источник — поле `version` в `package.json`; сервер передаёт его в ответе `/api/schedule`.

## Две недели и даты

Расписание колледжа чередует две недели. Какая из них приходится на нечётные ISO-недели года, задаёт `ODD_ISO_WEEK_IS` в `lib/weekCycle.js` (в клиенте то же значение хранится в `CONFIG.oddIsoWeekIs` файла `public/app.js`). Все расчёты ведутся по московскому времени.

Правки в админке привязаны к календарной неделе (ключ вида `2026-W44`), а не к номеру недели расписания: правка к «Неделе 1» действует только на ближайшую неделю с этим номером и автоматически перестаёт применяться, когда она заканчивается. В редакторе доступны две недели — текущая и следующая, с реальными датами.

## Как определяются отметки об изменениях

- **Автоматически (сайт колледжа).** При каждой загрузке расписание сравнивается со снимком, сохранённым в `data/changes.json`. Пары, которых в снимке не было, получают отметку. Если колледж указал время обновления страницы, оно и становится временем изменения; иначе берётся момент обнаружения. Первая загрузка группы только создаёт снимок. Если хранилище недоступно, расписание выдаётся без отметок.
- **Вручную (админка).** При сохранении сервер сравнивает отправленные пары с прежними правками и с данными колледжа. Новые и изменённые пары получают отметку; не тронутые пары сохраняют прежнюю. Пара, совпавшая с расписанием колледжа, отметки не получает.

Отметка действует 24 часа и проверяется как на сервере, так и в браузере.

## Админка (`/admin`)

- Выпадающий список групп: выбирается группа, в которой нужно сделать замену.
- Две недели с датами, полоса дней, карточки пар. Изменённые дни помечены, любой день можно вернуть к расписанию колледжа.
- Поле «Предмет или преподаватель» ищет сразу по предметам, фамилиям преподавателей и номерам групп. В списке для каждой записи указаны предмет, преподаватель и группы, у которых он есть; записи выбранной группы показываются первыми. После выбора предмет и преподаватель подставляются в карточку (без номера аудитории). Поле преподавателя тоже подсказывает варианты, значения можно вводить вручную.
- Автозаполнение через Gemini находится в правой колонке (на узких экранах — под редактором).
- На телефоне доступны выбор группы, поиск и срочные правки; автозаполнение скрыто.

### Автозаполнение по фотографии

1. В блоке «Автозаполнение через Gemini» выбирается режим: вся неделя (даты видны на фотографии) или один день (дата выбирается в панели).
2. Панель формирует промпт: правила разбора, список предметов и преподавателей группы, формат ответа. Его копируют и отправляют в Gemini вместе с фотографией расписания.
3. JSON из ответа вставляется в панель. Он проверяется, названия предметов и преподавателей сопоставляются с каталогом, дни с датами вне двух доступных недель отбрасываются, о спорных местах выводятся предупреждения.
4. Результат попадает в редактор, но не сохраняется, пока администратор не нажмёт «Сохранить».

Логика промпта и разбора ответа находится в `public/admin-assets/autofill.js` и покрыта тестами.

### Каталог групп, предметов и преподавателей

`data/catalog.json` — один файл для всех групп. Он собирается из расписаний всех групп на сайте колледжа (список групп берётся со страницы `bg.htm`) и содержит группы, предметы каждой группы с их преподавателями, аудитории и общий список преподавателей. Каталог обновляется не чаще раза в сутки при обращении к нему из админки; принудительное обновление ограничено интервалом в час. Если часть страниц не загрузилась, для этих групп остаются прежние данные, а при массовом сбое обновление отменяется.

## Статистика посещений

Страница `/admin/stats` (кнопка с числом «Сейчас онлайн» есть и в самой админке) показывает: кто сейчас на сайте, уникальных посетителей за сегодня / неделю / 30 дней, график по дням, список посетителей (страна с флагом, устройство, IP, какие группы смотрели), географию и устройства. IP по умолчанию скрыт (`95.XX.XX.42`) — нажми на него, чтобы увидеть целиком. Список можно выгрузить в CSV.

### Как это считается

- Страница сайта при открытии и затем раз в 30 секунд, пока ей пользуются, отправляет на сервер короткий анонимный сигнал «я тут, смотрю группу 841». Через 5 минут без действий или при сворачивании вкладки сигналы прекращаются, а при закрытии уходит сигнал «ушёл» — поэтому короткие заходы тоже видны, а забытая открытой вкладка ничего не нагружает.
- «Онлайн» — сигнал был за последнюю минуту и посетитель не «ушёл».
- Посетитель определяется идентификатором, который сайт сохраняет в браузере (localStorage); IP хранится рядом и обновляется, если сменился. Если localStorage недоступен, посетитель определяется по IP и браузеру.
- Страну отдаёт сам Vercel (по IP, приблизительно — через VPN она будет другой), устройство определяется по User-Agent с поправкой на подсказки браузера и данные страницы (сенсорный экран, размер экрана): так iPad и телефон в режиме «версия для ПК» не принимаются за компьютер. Рядом со страной показывается браузер посетителя.
- Адрес сигнала нарочно нейтральный (`/api/visit`): блокировщики рекламы режут адреса со словом «track». Если посетитель всё равно не попал в статистику, причина видна в заголовке `X-Visit-Skip` ответа (DevTools → Network), а на странице статистики появляется блок «Не засчитано» с причиной и последним примером браузера. Прежний адрес `/api/track` оставлен для устройств с устаревшей версией сайта в кэше.
- Не считаются: боты, ваши собственные заходы, пока вы залогинены в админку, и сама админка. Запросы с чужого origin отклоняются, а с одного IP принимается не больше 300 сигналов в минуту.
- Все данные автоматически удаляются через 30 дней после последнего захода посетителя.

IP-адрес — персональные данные (в том числе по GDPR для посетителей из ЕС), поэтому срок хранения ограничен и просмотр закрыт логином.

### Подключение (один раз, бесплатно)

Данные хранятся в Upstash Redis (отдельно от данных расписания, которые лежат в GitHub) — базе, которая подключается к Vercel в несколько кликов. Бесплатный тариф: 500 000 команд в месяц; для 5–20 посетителей используется в разы меньше (один сигнал — 2 команды).

1. Vercel → твой проект → вкладка **Storage** → **Create Database** → **Upstash** → **Redis** → тариф **Free** → **Create**.
2. Подключи базу к проекту (**Connect Project**, окружения оставь все). Vercel сам добавит нужные переменные `KV_REST_API_URL` и `KV_REST_API_TOKEN`.
3. **Deployments** → у последнего деплоя ⋯ → **Redeploy** (переменные применяются только после пересборки).
4. Открой `/admin/stats` — до подключения там будет подсказка, после — данные начнут появляться с первого же захода на сайт.

Без подключения сайт и админка работают как обычно, просто без статистики.

## Настройки сайта (`/admin/settings`)

Открываются карточкой «Настройки сайта» на главной странице админки (она же показывает, если сайт выключен или закрыт паролем). Настройки хранятся в Upstash Redis — том же, что нужен для статистики, — поэтому переключатели действуют **без публикации новой версии**. Без Redis страница открывается, но сохранить настройки нельзя.

- **Сайт временно не работает.** Галочка + текст, который увидят посетители (до 500 символов). Страница отдаётся с кодом 503 и подсказкой «зайдите позже» для поисковиков. Администратор, пока вошёл в админку, видит сайт как обычно.
- **Доступ по паролю.** Галочка, один общий логин и пароль для посетителей (пароль хранится только хешем scrypt, как и пароль админа). Без входа посетитель видит лишь форму входа; закрыты и сами страницы, и `/api/schedule`, `/api/groups`. Вход запоминается на 7 дней (cookie `visitor_session`, подписана ключом, производным от секрета админа). Смена логина или пароля, а также кнопка «Выйти у всех посетителей» сразу завершают все сессии. Попытки подбора ограничены: 20 ошибок за 15 минут с одного IP (запас большой — в колледже много людей выходят с одного адреса). Администратору отдельный вход не нужен.
- **Журнал посещений.** Срок хранения записей (1–90 дней, по умолчанию 30). Если срок уменьшить, лишнее удаляется сразу.
- **Очистка журнала** — страница статистики, вкладка «Очистка» и галочки на вкладке «Посетители»: удалить выбранных, удалить записи «старше N дней» или «только за последние N дней» (по времени последнего визита), очистить всё.

Если включены оба режима, заглушка сильнее входа по паролю.

**Как это устроено.** Страница сайта лежит в `views/index.html`, а не в `public/`: файлы из `public/` Vercel отдаёт напрямую, минуя любые проверки. Адреса `/` и `/index.html` переписываются на функцию `api/gate.js`, которая решает, что показать: сайт, форму входа или заглушку. Настройки кэшируются в памяти функции на 15 секунд — поэтому изменение вступает в силу в течение этого времени. Если Redis недоступен, используются последние известные настройки, а при их отсутствии сайт остаётся открытым.

**Ограничения.**
- Ответы `/api/schedule` и `/api/groups` в обычном режиме кэшируются на CDN (чтобы не нагружать сайт колледжа), а CDN отдаёт кэш, не запуская функцию. Поэтому в момент включения заглушки или пароля уже закэшированные ответы API могут ещё отдаваться тем, кто обращается к ним напрямую, — до 30 минут в учебные часы и до 2 часов в остальное время. Сами страницы закрываются сразу. При включённом ограничении API больше не кэшируется на CDN.
- Сайт защищён одним общим паролем: это отсекает посторонних и ботов, но не различает отдельных людей.
- Если на GitHub остался старый файл `public/index.html`, он будет отдаваться напрямую и обойдёт проверку. Страница настроек сама предупредит об этом красным сообщением; такой файл нужно удалить (подробнее — в разделе «Развёртывание»).

## Страница 404

`public/404.html` показывается для любого несуществующего адреса: «Страница не найдена» и кнопка «На главную». Файл генерируется из `lib/pages.js` (там же заглушка и форма входа); тест следит, чтобы они не расходились: `node -e "require('fs').writeFileSync('public/404.html', require('./lib/pages').notFoundHtml())"`.

## Безопасность

- Учётные данные не хранятся в коде и репозитории: имя администратора и пароль задаются переменными окружения в настройках хостинга, где значения закрыты от посторонних. Вместо открытого пароля можно задать его хеш (scrypt). Пока учётные данные не заданы, вход отключён.
- Сессия — подписанная cookie с флагами `HttpOnly`, `Secure`, `SameSite=Strict`, срок 14 дней. Ключ подписи зависит от пароля, поэтому его смена завершает все сессии.
- Сравнение логина и пароля выполняется за постоянное время; неудачные попытки замедляются и ограничиваются по IP (ограничение приблизительное: состояние хранится в памяти экземпляра функции).
- Запросы на изменение данных принимаются только с того же origin.
- Все эндпоинты админки требуют действующую сессию и не кэшируются.
- Страница админки отдаётся с CSP без встроенных скриптов; для публичной страницы также задан CSP и заголовки защиты (см. `vercel.json`).
- Страница статистики отдаётся с такой же строгой CSP (без встроенных скриптов и стилей; дополнительно разрешены только флаги с `cdn.jsdelivr.net`), данные доступны только с сессией. Публичный `/api/visit` принимает запросы только с того же origin, ограничен по частоте и всегда отвечает 204.
- Вход посетителей и страница настроек защищены так же, как вход в админку: проверка origin у запросов на изменение, хеширование scrypt, подписанные cookie с привязкой к версии, ограничение числа попыток. Текст заглушки при выводе экранируется.
- IP-адреса — персональные данные: они хранятся не дольше 30 дней и скрыты в интерфейсе до нажатия.
- Данные из ответа нейросети и из форм проходят серверную очистку (`lib/lessons.js`): длина полей, номер пары, подгруппа.
- Токен GitHub нужен только с правом записи содержимого (Contents) этого репозитория.

## Переменные окружения

| Переменная | Назначение |
| --- | --- |
| `ADMIN_USER` | имя администратора |
| `ADMIN_PASSWORD` | пароль не короче 12 символов |
| `ADMIN_PASSWORD_HASH` | необязательно: хеш пароля в формате scrypt вместо `ADMIN_PASSWORD` |
| `SESSION_SECRET` | необязательно: случайная строка не короче 32 символов для подписи сессий |
| `GITHUB_TOKEN` | токен с правом Contents: Read and write |
| `GITHUB_REPO` | репозиторий в формате `владелец/имя` |
| `GITHUB_BRANCH` | ветка с данными (по умолчанию `main`) |
| `GITHUB_DATA_DIR` | каталог с файлами данных (по умолчанию `data`) |
| `KV_REST_API_URL`, `KV_REST_API_TOKEN` | необязательно: добавляются автоматически при подключении Upstash Redis (допустимы и `UPSTASH_REDIS_REST_*`); без них статистика отключена |

Значения добавляются в настройки проекта на Vercel (Settings → Environment Variables), после чего нужно повторно развернуть проект. Для хранения хеша вместо открытого пароля служит команда `npm run admin:setup`: пароль вводится в терминале без отображения, результат выводится только на экран.

## Развёртывание

1. Импортировать репозиторий в Vercel.
2. Задать переменные окружения из таблицы выше.
3. Рекомендуется хранить данные в отдельной ветке (например, `data`) и указать её в `GITHUB_BRANCH`: в `vercel.json` для ветки `data` отключено развёртывание, поэтому служебные коммиты не вызывают пересборку сайта. Ветку нужно создать заранее.
4. Функция каталога может работать до минуты (`maxDuration` в `vercel.json`).
5. **При обновлении с версии 1.3.x** на GitHub нужно вручную **удалить** два устаревших файла (простая заливка архива «поверх» их не удаляет): `public/index.html` (страница сайта переехала в `views/index.html`; пока старый файл на месте, он отдаётся напрямую и проверка доступа обходится) и `api/track.js` (на бесплатном тарифе Vercel не больше 12 функций, лишний файл не даст опубликоваться). В репозитории есть `.vercelignore`, который исключает оба файла из публикации, но удалить их всё равно стоит.
6. Для статистики и настроек сайта подключить Upstash Redis (см. раздел «Статистика посещений»). Без этого шага всё остальное работает как обычно.

## Как часто опрашивается сайт колледжа

Ответ `/api/schedule` кэшируется на CDN: 30 минут в учебные часы (6:00–17:00 МСК) и 2 часа в остальное время (`lib/refreshWindow.js`; те же значения в `public/app.js`). Кнопка «Обновить» обходит кэш, но не чаще раза в минуту на всех.

## Исправления данных колледжа

`lib/fixes.js` содержит точечные исправления известных ошибок на сайте колледжа (например, номера подгрупп). Правила срабатывают только при совпадении группы, предмета и преподавателя; при изменении расписания колледжа они молча перестают применяться.

## Структура

```text
api/                  серверные функции (gate, schedule, groups, visit, admin*, admin-stats; всего не больше 12)
lib/                  разбор сайта колледжа, недели, правки, отметки, каталог, авторизация, хранилище
views/                страница сайта index.html (отдаётся через api/gate.js)
public/               статические файлы сайта (стили, скрипт, иконки, 404.html); admin-assets/ — интерфейс админки, страница статистики, логика автозаполнения
scripts/              setup-admin.js (создание хеша пароля), run-tests.js
test/                 тесты (node:test)
data/                 данные админки (JSON), создаются автоматически
```

## Версия приложения

Номер версии задаётся полем `version` в `package.json` (формат `МАЖОР.МИНОР.ПАТЧ`). После изменения значения и нового развёртывания он появляется в нижней части страницы сайта.

## Разработка

```bash
npm install
npm test
```

Тесты используют встроенный раннер Node.js. Для проверки серверной логики сайт колледжа и GitHub подменяются заглушками (`test/helpers/fakes.js`), поэтому сеть не требуется; `test/parse.test.js` проверяет разбор HTML и требует установленных зависимостей.
